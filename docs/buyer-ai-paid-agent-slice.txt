What works in this slice
The existing apps/rel8tion-app/agent-home.html personal agent dashboard now has a downstream Buyer Relationship Assistant section on its explicit local fixture entry. The original renderShell(), NFC/phone gates and production initialization are retained. There is no new standalone HTML application.

The server-owned fixture contexts include two synthetic agent workspaces, two event-history rows, event/profile leads, originating agent versus substitute host, canonical-contact crosswalk fields, membership, representation, SMS/email consent and separate LO context. Paid-agent lead lists appear together in the new section. These are simulated resolver outputs, not imports from the real OS or application database.

Run eligible follow-up starts one contextual conversation per eligible synthetic buyer. Both SMS/email are simulated when independently permitted; an email address alone does not grant email permission. The same agent's existing verified buyer can receive service; another/unknown agent relationship is held. Buyer replies retain exact sourced preference quotes, match the fictional property catalog and produce explicit agent-review opportunities. Showing/offer preparation is never represented as booking or submission. Pause, takeover, revocation, STOP and email unsubscribe alter future preview behavior without notifying anyone.

Code map
- lib/buyer-ai/fixtures.js: server-owned synthetic data only; no database/provider imports.
- lib/buyer-ai/service.js: per-workspace checks, serialized actions, idempotency, conversation state, sourced facts, matches and handoff; no delivery adapter.
- lib/buyer-ai/model.js: AI SDK 7.0.163 generateText boundary and explicit offline fixture language model. generateWithModel is an injection seam; no real provider/model is configured or tested. Input is contextual but this fixture's language behavior is deterministic; do not present it as live LLM intelligence.
- api/buyer-ai-preview.js: disabled default export; only dedicated loopback server enables fixtures. Rejects Vercel, non-loopback hosts/clients, foreign origins, missing fixture session or wrong CSRF token. Actor comes from the server session rather than POST data.
- apps/rel8tion-app/src/modules/buyerAi/workspace.js: actual agent-home add-on UI; existing navigation is inert only in fixture mode.
- scripts/serve-buyer-ai-preview.cjs: loopback allowlist; only the new fixture API and required static source/assets. Production routes, credentials and databases are not mounted.
- test/buyer-ai-workspace.test.cjs: focused integration/security/policy/model tests.
